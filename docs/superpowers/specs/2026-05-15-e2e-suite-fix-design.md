# E2E Suite Fix — Design Spec

**Date:** 2026-05-15
**Status:** Approved (autonomous execution authorized)
**Branch:** `feature/nav-redesign`

## Goal

Bring the Playwright e2e suite (`tests/e2e/`) to green so it can serve as a real make-it-live gate. Three issues remain after the deeper investigation that produced commits `4d6841a` (heading regression fix) and `8ff6f12` (`is_logistics_or_admin` regression fix):

1. `inventory.spec.ts:16` and `:49` use a no-op sync assertion → race against an async server action → page redirects.
2. `rostering.spec.ts` and `recurring.spec.ts` reference `tests/e2e/.auth/admin.json` / `member.json` storage state files that nothing generates and no setup project produces. 11 tests broken.
3. `people.spec.ts:43` (and its surrounding describe) tests "invite with teams" — a feature that no longer exists in `InviteForm.tsx`.

After the fix, `npx playwright test` should be all-green against a fresh `supabase db reset` and serve as the live gate in `make-it-live`.

## Why now

`make-it-live` ran first; the e2e suite blocked it. Triage uncovered a production-breaking bug (`is_logistics_or_admin` referencing the dropped `role` column) — already fixed. Remaining failures are pre-existing test rot, but blocking deploy on rot is wrong, and a permanently-broken e2e suite has zero signal value. Fix it now or admit the suite isn't a gate.

### Auth setup pattern

Playwright's recommended pattern for storage-state setup is a `setup` project listed as a `dependency` of the test projects:

```ts
// playwright.config.ts (the projects array becomes)
projects: [
  { name: "setup", testMatch: /auth\.setup\.ts/ },
  { name: "chromium", use: { ...devices["Desktop Chrome"] }, dependencies: ["setup"] },
],
```

`auth.setup.ts`:
```ts
import { test as setup } from "@playwright/test";
import * as path from "path";

const adminFile  = path.join(__dirname, ".auth/admin.json");
const memberFile = path.join(__dirname, ".auth/member.json");

setup("authenticate as admin", async ({ page }) => {
  await page.goto("/login");
  await page.getByLabel("Email").fill("admin@commune.local");
  await page.getByLabel("Password").fill("commune-admin-dev");
  await page.getByRole("button", { name: "Sign in" }).click();
  await page.waitForURL("/dashboard");
  await page.context().storageState({ path: adminFile });
});

setup("authenticate as member", async ({ page }) => {
  await page.goto("/login");
  await page.getByLabel("Email").fill("member@commune.local");
  await page.getByLabel("Password").fill("test-pass-dev");
  await page.getByRole("button", { name: "Sign in" }).click();
  await page.waitForURL("/dashboard");
  await page.context().storageState({ path: memberFile });
});
```

Existing `test.use({ storageState: "tests/e2e/.auth/admin.json" })` calls in `rostering.spec.ts` and `recurring.spec.ts` then resolve to the freshly-generated files.

### Bug 2 fix (inventory tests)

The current assertion `expect(page.locator('input[name="name"]').last()).toHaveValue(catName)` is a no-op — on an empty table, the only `input[name="name"]` is the input that was just typed into, so it trivially passes at `t=0` without confirming a server commit. Replace with a wait for the saved-category row's "Delete" button (which only renders post-commit):

```diff
  await page.getByRole("button", { name: "Add" }).click();
- await expect(page.locator('input[name="name"]').last()).toHaveValue(catName);
+ await expect(page.getByRole("button", { name: "Delete" }).first()).toBeVisible();
  await page.goto("/inventory/manage/items/new");
```

Apply at line 23 (preceding the line 27 `selectOption`) and at the equivalent step in the line-49 reservation-flow test.

### Obsolete test removal

Delete the entire `test.describe("Invite with teams", ...)` block in `people.spec.ts`. The `InviteForm.tsx` component no longer has any team-related fields; team membership is assigned via team-position records through the rostering UI, not the invite form. The test isn't testing a real product path.
